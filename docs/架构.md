# CovTrace 架构

把 `cov` 的行覆盖能力和 `verysleep` 的函数边能力装进同一个
clang 构建产物，再由一套“引擎 + 对接闸门 + 翻译卡片”的脚本编排。

> 约束：AI 只写求值脚本；引擎负责跑工程和编排；产物按节点分目录落盘。
> 本文件只描述架构，不包含实现。

---

## 1. 术语

| 名称 | 英文/目录 | 运行位置 | 职责 |
|---|---|---|---|
| 引擎 | `engine.py` | 宿主 Python | 只做编排：校验重复、启动 Blender、按顺序跑翻译卡片、写 manifest |
| 对接闸门 | `gates/` | Blender 内 | 每个闸门管一组编译产物导出的钩子，自己 arm/dump，产出 raw |
| 翻译卡片 | `cards/` | 宿主 Python | 一张卡只产出一个最终 JSON；卡之间按顺序消费 |
| 基础设施 | `infra/` | 宿主 Python | 路径、hash、subprocess、manifest、日志 |
| 底座 | `bootstrap.py` | Blender 内 | 加载求值脚本、注入 helper、按顺序 arm 闸门、执行、dump |
| 求值脚本 | `eval/*.py` | Blender 内 | AI 提供；只写业务求值，不碰 ctypes/文件 |

**核心原则**：闸门和卡片互不知道对方。新增一个能力 = 新增闸门/卡片模块
+ 在 `registry.py` 里注册；不修改其他闸门和卡片。

注册是开发者在 `registry.py` 里显式写死的，不做自动扫描/插件发现。
运行时用户（AI）只传求值脚本和节点，不接触注册表。

## 2. 总体数据流

```text
AI
 │  eval.py + --node boolean
 ▼
engine.py（宿主）
 │  1. 读 eval 的 TARGET，算 run key / hash8
 │  2. 检查 out/boolean/<hash8>/ 是否已存在
 │  3. 建临时工作目录
 │  4. 启动 Blender（不传 blend）
 ▼
blender --background --python bootstrap.py -- \
        --eval <eval.py> --work <temp> --node <node>
 │
 │  bootstrap.py（Blender 内）
 │    ├─ 读 TARGET，打开 blend（开窗前）
 │    ├─ 加载 eval.py，构造 ctx
 │    ├─ 依次 arm 已注册闸门
 │    ├─ evaluate(ctx)
 │    └─ 反序 dump 已注册闸门
 ▼
engine.py
 │  按顺序跑翻译卡片：
 │    edge     : raw -> edge.json                    公开
 │    disasm   : raw -> disasm.json                  内部（--test 公开）
 │    coverage : raw -> coverage.json                公开
 │    timing   : raw -> timing.json                  内部（--test 公开）
 │    metrics  : disasm.json + timing.json + edges.bin
 │               -> functions.jsonl                  公开
 │    filter   : functions.jsonl -> filter.json      公开
 │  全部成功 -> 删除 _internal/，把暂存目录改名成 out/<node>/<hash8>/
 ▼
out/<node>/<hash8>/
```

工程、物体、修改器、参数都写在 eval 的 `TARGET` 里；blend 由
bootstrap 在开窗前打开，窗口内只有求值代码。

## 4. 接口契约

### 4.1 对接闸门

在 Blender 内运行，只能使用 `bpy`、`ctypes` 和标准库。

```python
class Gate:
    name: str
    exports: tuple[str, ...]   # 缺任意一个就报错，列出缺失符号

    def arm(self, ctx): ...
    def dump(self, ctx): ...
```

- 引擎注册闸门实例后，把 `module:Class` 字符串传给 bootstrap；
  bootstrap 动态导入、实例化，并逐个校验 `exports`，缺一个就列出
  “闸门名 + 缺失符号”。
- `bootstrap.py` 按注册顺序 arm，执行求值，再**反序** dump。
- 闸门只负责“开窗 / 关窗 / 落 raw”，不解析 raw。
- 新能力 = 新增 `gates/xxx.py` 并在 `registry.py` 注册，其他闸门不动。

### 4.2 翻译卡片

在宿主 Python 运行，不依赖 `bpy`。

```python
class TranslationCard:
    name: str
    needs: tuple[str, ...]     # raw key 或前一张卡的产物
    def build(self, ctx) -> dict: ...
```

- `needs` 约定：`raw:functions` / `raw:edges` 指向闸门 raw；
  `edge` / `metrics` 等逻辑产物名指向前序卡片的登记产物。
- `CardContext` 提供 `raw(key)`、`out(key)`、`input(key)`、
  `publish(key)`、`internal(key)`、`test`、`target`、`node`、
  `blender`、`pdb`，卡片只使用逻辑产物名，不直接决定文件位置。
  - 产物的相对路径和 `internal` 属性统一登记在 `registry.py` 的 `PRODUCTS`；
  - `publish(key)`：内部产物默认写 `_internal/`，`--test` 时写登记的公开位置；
  - `input(key)`：按登记规则和 `--test` 找到前序产物；
  - 默认模式下 `_internal/` 在全部卡片跑完后由引擎删除。
- 卡片写暂存目录；全部成功后引擎把 `.<hash8>.tmp` 改名为 `<hash8>`，
  失败则删除暂存目录、保留 work raw。
- 引擎按注册顺序执行，并检查登记产物确实已写入；新增卡片 =
  新增 `cards/xxx.py`，再在 `registry.py` 登记卡片和产物。
- 卡片固定顺序：`edge -> disasm -> coverage -> timing -> metrics ->
  filter -> diff`。其中 disasm / timing 是内部中间产物，只有 `--test` 才发布到
  顶层；没有对比基线时 diff 跳过。

### 4.3 求值脚本（接口 B）

目标信息和业务求值都写在同一个脚本里。`TARGET` 必须是**字面量字典**
（引擎在宿主侧用 AST 读取，不执行脚本）。

```python
TARGET = {
    "blend": r"C:\...\破碎修改器.blend",
    "object": "破碎立方体",
    "modifier": "破碎",
    "param": "碎片数量",
    "node_tree": "",   # 可选；留空表示用修改器的 node_group
}

NODE = "设置位置"  # 可选；填写后普通 run 自动执行 before/after 并生成 diff.json

def evaluate(ctx):
    for v in (20, 40):
        ctx.set_value(v)
        print(v, ctx.instance_count())
```

`ctx` 由底座注入：

| 字段 | 说明 |
|---|---|
| `ctx.bpy` | `bpy` 模块 |
| `ctx.target` | TARGET 的完整字典（含 CLI 覆盖后的生效值） |
| `ctx.obj` | 物体对象，来自 `TARGET["object"]` |
| `ctx.mod` | 修改器对象，来自 `TARGET["modifier"]` |
| `ctx.param` | 参数显示名，来自 `TARGET["param"]` |
| `ctx.set_value(v)` | 设参数并触发一次求值，返回耗时 ms |
| `ctx.instance_count()` | 当前 depsgraph 的实例数 |

- `TARGET["param"]` 用显示名，底座负责解析成真正的 socket identifier。
- `NODE` 是要测量边界的几何节点，可写节点名、label 或 bl_idname；它与
  CLI 中只用于输出目录命名的 `--node` 不是同一个概念。
- `--blend/--obj/--mod/--param` 仍可作为可选覆盖项。
- `evaluate` 内可以多次求值；当前设计为**一个累计窗口**。

## 5. 运行流程

```text
python engine.py run --eval eval\frag2.py --node boolean \
  [--blend ... --obj ... --mod ... --param ...] \
  [--blender D:\blender-src\build_windows_x64_ClangCovTrace\bin\blender.exe] \
  [--out out] [--test]
```

eval 中写了 `NODE` 时，上述普通命令自动执行 before → after → diff，无需
额外 CLI 参数；after 目录会包含 `diff.json`。没有 `NODE` 时保持单次采集，
并跳过 boundary 区域校验、节点解析/rewire 和 diff。

1. 读取 eval 的 `TARGET` 和文件内容，算 `run_key`。
2. 计算 `hash8 = run_key[:8]`。
3. `out/<node>/<hash8>/run.json` 已存在且 key 相同：
   报错“你要的东西已经跑过了”，并打印目录。
4. 建 cache 工作目录 `cache/<node>/<hash8>.tmp/`。
5. 启动 Blender（不传 blend），传入 bootstrap、eval、node、work，
   以及闸门的 `module:Class` 列表。
6. bootstrap 读 TARGET、打开 blend、校验 object/modifier/param、
   解析 socket identifier、构造 ctx；然后 arm 闸门 → evaluate →
   反序 dump，落 raw 和 `status.json`。
7. 引擎做硬检查（`edge_count`、`functions.bin`、`window.profraw`），
   然后按顺序跑卡片，全部写入暂存输出目录。
8. 成功：暂存目录改名 `out/<node>/<hash8>/`，work 改名
   `cache/<node>/<hash8>/`；失败：work 改名
   `cache/<node>/<hash8>.failed-<timestamp>/`，保留现场。
9. 已有成功 cache 时，可以只重跑翻译，不启动 Blender：

```text
python engine.py translate cache/<node>/<hash8> [--out out] [--test]
```

- `--test`：把 `disasm.json` / `timing.json` 发布到输出目录顶层。默认它们
  只写到 `_internal/`，卡片跑完后删除；该选项不参与 `run_key`，不影响
  缓存复用。

## 6. 交互规则

### 6.1 节点名

- `--node` 用于输出目录命名。
- 目录名安全化：非 `[A-Za-z0-9_.-]` 替换为 `_`。
- 卡片失败时 raw 保留（见第 9 节），可只重跑翻译。

### 6.2 重复判定

```text
run_key = sha256(
    eval 内容
    + node
    + 构建指纹（exe/PDB 路径、大小、mtime）
    + 生效的 TARGET（含 CLI 覆盖）
)
hash8 = run_key 前 8 位
```

- 同一节点、同一脚本、同一构建 → 同一 `hash8` → 报错。
- 同一节点、不同脚本或不同构建 → 不同 `hash8` → 新目录。
- 失败重跑：允许 `--force` 覆盖同一 `hash8`（可选实现）。

### 6.3 产物命名

`out/<node>/<hash8>/` 下：

| 文件 | 默认可见 | 内容 |
|---|---|---|
| `edge.json` | 是 | `meta / files / functions[].{...,rva,va} / edges[].{caller,callee,caller_rva,callee_rva}` |
| `disasm.json` | 否（`--test` 是） | `meta / functions[].{rva,name,file,line,module,disasm{...}}` |
| `coverage.json` | 是 | `meta / files[path].{count,ranges}`（执行行） |
| `timing.json` | 否（`--test` 是） | `meta / functions[].{rva,count,total_self_ns,total_inclusive_ns,mean_self_ns,mean_inclusive_ns,self_share}` |
| `functions.jsonl` | 是 | 首行 `_meta`，之后一行一个函数，主键 `rva` |
| `filter.json` | 是 | `meta / kept[] / dropped[]`，rva 决策列表 |
| `diff.json` | eval 含 `NODE` 时在 after 目录生成 | before/after 的函数和调用边增删差异 |
| `run.json` | 是 | manifest：key、路径、时间、计数、卡片状态、`products` |

说明：

- 默认发布 edge / coverage / functions.jsonl / filter.json；eval 含 `NODE`
  时 after 运行还发布 diff.json；disasm / timing 写到 `_internal/`，卡片跑完后删除。
- 函数身份统一用 `rva`。`functions.bin` 存的是 `rva + 1`，
  `edges.bin` 是原始 `rva`；`edge` 卡片读取 `functions.bin` 时会减 1。
- `edge.json` 的符号键是 `rva`，不再按 `(name,file,line)` 合并；当前
  2,330 个函数都是独立记录。
- 不再产出 `only_call.json`；出度统一看 `functions.jsonl.out_degree`。
- `no_edge`、独立的 `start.json` / `finally.json` 仍不产出。

## 7. 闸门与窗口细节

### 7.1 v1 闸门

| 闸门 | 导出符号 | raw 产物 |
|---|---|---|
| `calls` | `covtrace_calls_arm/reset/disarm/dump/dump_edges/dump_timings/edge_count/timing_count` | `functions.bin`、`edges.bin`、`timings.bin`、`calls.json` |


- 行覆盖和函数边来自同一次执行、同一个窗口。
- 函数钩子使用 `-finstrument-functions-after-inlining`，caller 为函数入口。

## 8. 翻译卡片

### 8.1 edge

- 输入：`functions.bin`、`edges.bin`、exe/PDB。
- 输出：`edge.json`。
- `functions.bin` 每条是 `rva + 1`，读取时减 1；`edges.bin` 是原始 `rva`。
- 符号按 **rva** 去重，不再按 `(name,file,line)` 合并；`functions[]` 带
  `rva / va`，`edges[]` 带 `caller_rva / callee_rva`。当前 2,330 个函数、
  4,356 条边。

### 8.2 coverage

- 输入：`window.profraw`、exe/PDB。
- 输出：`coverage.json`（`meta / files[path].{count,ranges}`）。
- 闸门 `gates/coverage.py`：`covtrace_arm` / `covtrace_dump`，
  与 calls 闸门在同一个求值窗口内采集。
- 卡片 `cards/coverage.py`：profraw → profdata → llvm-cov show →
  执行行区间；LCOV 导出用于函数计数。
- `profdata / cov_show.txt / lcov` 只放临时目录，成功后删除。
- `run --keep-all` / `translate --keep-all`：`coverage.json` 不再限制
  `source/` + `intern/`，`extern/` 和构建目录的执行行也会保留；默认仍只保留
  `source/` + `intern/`。`run` 时该选项计入 run key。
- 与其他卡片独立；已注册在引擎默认卡片列表里。

### 8.3 timing

- 输入：`timings.bin`、exe/PDB。
- 输出：`timing.json`，默认写 `_internal/`，`--test` 才发布。
  每条记录带 `rva`，内容为 `run.json` 之外的 `meta / functions[]`。
- 闸门 `gates/calls.py` 在 dump 阶段导出 `timings.bin`。每条记录是：
  `rva+1 / count / total_self / total_inclusive`，时间单位是 QPC ticks。
  文件头包含 magic `BTIM`、版本、QPC 频率、记录大小和记录数。
- 卡片 `cards/timing.py`：用 QPC 频率把 ticks 换成 ns，反解函数名，
  输出 `rva / count / total_self_ns / total_inclusive_ns / mean_self_ns /
  mean_inclusive_ns / self_share`，按 `mean_self_ns` 升序。
- `functions.jsonl` 只保留 `count / mean_self_ns / mean_inclusive_ns /
  self_share` 四个计时字段。
- `self` = inclusive − 直接子调用 inclusive，由 TLS 调用栈逐帧扣减。
  异常/longjmp、尾调用或内联可能导致缺失或偏差。
- **这里的 `self` 是 measured self，不是纯函数体 self**：它包含本函数
  enter/exit 钩子的 bookkeeping（TLS、claim、push/pop），但不包含
  `QueryPerformanceCounter` 调用本身；子调用的钩子开销会随子 inclusive
  一起被减掉；没有被插桩的 callee 时间会留在 self 里。
- 钩子开销**不是常数**。虽然是同一段 `bltrace_enter/exit` 代码，但首次
  claim/建表、哈希冲突、TLS 首次分配、线程竞争、缓存命中率和 CPU 频率
  都会改变单次开销。本次实测薄函数的地板约 30 ns；因此 100 ns 以下的
  绝对差异不可当真。薄函数只用于排序，判断纯转发应看 `self_share` 和
  caller/callee 的 inclusive 对比。
- 想更接近纯函数体 self，应把 `t0/t1` 移到 bookkeeping 之外，或用采样
  分析器交叉验证。
- 只有三个累计量，平均值就是 `total / count`；没有 max 或百分位，
  长尾单次调用会被平均掩盖。

### 8.4 disasm

- 输入：`functions.bin`、exe/PDB。
- 输出：`disasm.json`，默认写 `_internal/`，`--test` 才发布。
  每条记录为 `rva / name / file / line / module / disasm{...}`。
- 流程：
  1. `SymFromAddr` 取函数名、源码位置和 PDB `Size`（code size）；
  2. 解析 PE 头，把 RVA 映射到文件偏移；
  3. Capstone 反汇编 `Size` 字节，统计指令数、调用数、跳转/条件跳转、
     return 数和首尾指令；
  4. 识别 `__cyg_profile_func_enter/exit` 调用并从 `real_calls` 中扣除；
  5. 输出 `tiny / branchless / forwarder_candidate / tail_thunk` 标志；
     `tail_thunk` 只在 `tail_target_kind == direct_external` 时为真，本地
     `jmp`（循环/汇合边）不算。
- 同时输出更细的静态度量：`decoded_bytes / decode_error`、
  `padding_bytes / trailing_pad`、`direct_calls / indirect_calls`、
  `distinct_call_targets`、`runtime_calls / logic_calls`、
  `tail_target_kind`、`stack_frame_bytes / push_count`、
  `basic_blocks / back_edges`、`switch_tables`、
  `first_after_hook`、`hook_balance`、`fp_simd_insns / lock_insns`、
  `rip_relative_refs / global_refs`。
  `hook_balance` 是 `{enter, exit, balanced}` 对象。
- 已移除 `symbol.kind / tags` 和 `meta.symbol_kinds`：原先按 PDB 名字模式的
  分类在 `functions.bin` 子集上 0 命中，筛选不依赖它。名字来源与限制见
  `docs/筛选.md`。
- `forwarder_candidate` 的条件很保守：`size <= 128`、没有条件跳转、
  恰好 1 个真实调用、至少 1 个 return。
- 注意：当前二进制带函数插桩和 coverage，`size/instructions` 包含这些
  额外指令；只有 `real_calls` 扣除了函数插桩调用。纯转发在未插桩构建里
  可能只有一个 `jmp` 或几条指令，这里会看到固定地板。
- `tail_thunk` 只认 `tail_target_kind == direct_external`（首/末 `jmp` 指向
  函数外直接地址）。本地 `jmp` 是循环/汇合边，不计入；当前构建 0 命中。
- 各字段的可信度和组合判据见 `docs/筛选.md`。

### 8.5 metrics

- 输入：`disasm.json`、`timing.json`、`raw:edges`。
- 输出：`functions.jsonl`，首行 `_meta`，之后一行一个函数，主键 `rva`。
- 去重：一行一个函数入口 RVA；当前 2,330 行、2,330 个唯一 rva。
- 字段：身份（`rva / name / file / line / module`）+ 计时 4 个
  （`count / mean_self_ns / mean_inclusive_ns / self_share`）+
  `out_degree` + disasm 源字段，共 36 列。
- `out_degree` = `edges.bin` 中该 caller rva 的不同 callee 数；不再产出
  `only_call.json`（旧的 675 是按边行数算的，新口径为 699）。
- 派生字段不存入 jsonl，公式记录在 `_meta.derived_removed`：
  `calls / hook_calls / real_calls / logic_calls / only_call / branchless /
  tiny / forwarder_candidate / tail_thunk / decode_error / trailing_pad /
  hook_balanced`。
- `self_share` 虽可由两个均值派生，但按需求保留。

## 9. 中间数据策略

raw 不进 `out/`，放在独立的 cache：

```text
cache/<node>/<hash8>/
  functions.bin / edges.bin / timings.bin / window.profraw
  status.json / run.json / calls.json / coverage_raw.json
```

规则：

- 成功后保留 raw，便于只重跑翻译（尤其是 coverage 或卡片修复）。
- 失败时把 work 改名为 `<hash8>.failed-<timestamp>/`，保留现场。
- 每个节点默认保留最近 **5** 个 cache；`--keep-cache N` 可改，
  `0` 表示不清理。
- `--no-raw`：所有卡片成功后删除 raw（此时不能 translate）。
- `engine.py translate <cache_dir>`：用已有 raw 重跑翻译卡片，
  不启动 Blender；成功后原子替换 `out/<node>/<hash8>/`。

采集硬检查：`edge_count == 0`、`functions.bin` 为空、或
`window.profraw` 为空，都会判失败并保留 raw，避免“脚本没触发求值
但流程显示成功”。

引擎默认设置 `LLVM_PROFILE_FILE=NUL`，避免没有覆盖闸门时 Blender
在项目目录写出 `default.profraw`。

## 10. 错误处理

| 情况 | 行为 |
|---|---|
| 闸门缺导出符号 | 列出闸门名和缺失符号 |
| 重复 run key | 报错并打印已存在的 `out/<node>/<hash8>/` |
| node 解析歧义 | 列出所有候选函数全名 |
| 采集结果为空 | `edge_count=0` / `functions.bin` 空 / `window.profraw` 空 → 判失败，raw 改名 `.failed-*` 保留 |
| 卡片失败 | 不产生最终目录；raw 改名 `.failed-*` 保留 |
| Blender 退出码 `0xC0000409` | 视为正常；只要 raw 已完整写出就继续 |
| exe/PDB 不配对 | 翻译前检查，报错并停止 |

## 11. 扩展方式与“独立性”

### 11.1 注册在哪

闸门、卡片和产物只在根目录 `registry.py` 注册，例如：

```python
PRODUCTS = {
    "edge": Product("edge.json"),
    "disasm": Product("disasm.json", internal=True),
}

GATES = [CoverageGate(), CallsGate()]
CARDS = [
    CardRegistration(EdgeCard(), ("edge",)),
    CardRegistration(DisasmCard(), ("disasm",)),
]
```

- 调整产物位置只改 `PRODUCTS` 的 `path`，卡片和依赖声明不需要改文件名；
  路径可以包含子目录，由 `CardContext` 自动创建。
- `internal=True` 表示默认写入 `_internal/`，`--test` 时发布到登记的公开位置。
- 运行时用户（AI）**不做注册**，只传 `--eval` 和 `--node`。
- 不使用自动扫描/插件发现：闸门 arm 顺序、卡片执行顺序都是固定的，
  避免隐式行为和顺序不确定。

### 11.2 “独立”指什么

- **代码解耦**：闸门之间不互相 import；卡片之间不互相 import；
  卡片不 import 闸门。所有模块只依赖 `infra/` 和引擎传入的 ctx。
- **互不影响**：改一张卡片的实现、加一个新闸门，不需要改其他卡片/
  闸门的代码。
- **只在 registry.py 会合**：模块的先后顺序、启用与否和产物位置都由注册表决定。
- “独立”不是“运行时自己注册”，也不是“新增模块完全不用改任何现有代码”
  ——`registry.py` 里的登记是唯一的显式接入点。
