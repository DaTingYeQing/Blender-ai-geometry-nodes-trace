# CovTrace 架构

把 `cov` 的行覆盖能力和 `verysleep` 的函数边/return 边能力装进同一个
clang 构建产物，再由一套“引擎 + 对接闸门 + 翻译卡片”的脚本编排。

> 约束：AI 只写求值脚本；引擎负责跑工程和编排；产物按节点分目录落盘。
> 本文件只描述架构，不包含实现。

---

## 1. 术语

| 名称 | 英文/目录 | 运行位置 | 职责 |
|---|---|---|---|
| 引擎 | `engine.py` | 宿主 Python | 只做编排：校验重复、启动 Blender、按顺序跑翻译卡片、写 manifest |
| 对接闸门 | `gates/` | Blender 内 | 每个闸门管一组编译产物导出的钩子，自己 arm/dump，产出 raw |
| 翻译卡片 | `cards/` | 宿主 Python | 一张卡只产出一个最终 JSON；卡之间按顺序消费 |
| 基础设施 | `infra/` | 宿主 Python | 路径、hash、subprocess、manifest、日志 |
| 底座 | `bootstrap.py` | Blender 内 | 加载求值脚本、注入 helper、按顺序 arm 闸门、执行、dump |
| 求值脚本 | `eval/*.py` | Blender 内 | AI 提供；只写业务求值，不碰 ctypes/文件 |

**核心原则**：闸门和卡片互不知道对方。新增一个能力 = 新增闸门/卡片模块
+ 在 `engine.py` 里加一行注册；不修改其他闸门和卡片。

注册是开发者在 `engine.py` 里显式写死的，不做自动扫描/插件发现。
运行时用户（AI）只传求值脚本和节点，不接触注册表。

## 2. 总体数据流

```text
AI
 │  eval.py + --node boolean
 ▼
engine.py（宿主）
 │  1. 读 eval 的 TARGET，算 run key / hash8
 │  2. 检查 out/boolean/<hash8>/ 是否已存在
 │  3. 建临时工作目录
 │  4. 启动 Blender（不传 blend）
 ▼
blender --background --python bootstrap.py -- \
        --eval <eval.py> --work <temp> --node <node>
 │
 │  bootstrap.py（Blender 内）
 │    ├─ 读 TARGET，打开 blend（开窗前）
 │    ├─ 加载 eval.py，构造 ctx
 │    ├─ 依次 arm 已注册闸门
 │    ├─ evaluate(ctx)
 │    └─ 反序 dump 已注册闸门
 ▼
engine.py
 │  按顺序跑翻译卡片：
 │    edge     : raw -> edge.json
 │    return   : edge.json + raw -> return.json
 │    between  : edge.json + return.json + node -> between.json
 │    coverage : raw -> coverage.json
 │  全部成功 -> 把暂存目录改名成 out/<node>/<hash8>/
 ▼
out/<node>/<hash8>/
```

工程、物体、修改器、参数都写在 eval 的 `TARGET` 里；blend 由
bootstrap 在开窗前打开，窗口内只有求值代码。

## 4. 接口契约

### 4.1 对接闸门

在 Blender 内运行，只能使用 `bpy`、`ctypes` 和标准库。

```python
class Gate:
    name: str
    exports: tuple[str, ...]   # 缺任意一个就报错，列出缺失符号

    def arm(self, ctx): ...
    def dump(self, ctx): ...
```

- 引擎注册闸门实例后，把 `module:Class` 字符串传给 bootstrap；
  bootstrap 动态导入、实例化，并逐个校验 `exports`，缺一个就列出
  “闸门名 + 缺失符号”。
- `bootstrap.py` 按注册顺序 arm，执行求值，再**反序** dump。
- 闸门只负责“开窗 / 关窗 / 落 raw”，不解析 raw。
- 新能力 = 新增 `gates/xxx.py` 并在 `engine.py` 注册，其他闸门不动。

### 4.2 翻译卡片

在宿主 Python 运行，不依赖 `bpy`。

```python
class TranslationCard:
    name: str
    needs: tuple[str, ...]     # raw key 或前一张卡的产物
    def build(self, ctx) -> dict: ...
```

- `needs` 约定：`raw:functions` / `raw:edges` 指向闸门 raw；
  `edge.json` 指向前序卡片的产物。
- `CardContext` 提供 `raw(key)`、`out(name)`、`target`、`node`、
  `blender`、`pdb`，卡片不直接拼路径。
- 卡片写暂存目录；全部成功后引擎把 `.<hash8>.tmp` 改名为 `<hash8>`，
  失败则删除暂存目录、保留 work raw。
- 引擎按注册顺序执行；新增卡片 = 新增 `cards/xxx.py` 并注册。
- v1 卡片固定顺序：`edge -> return -> between -> coverage`。

### 4.3 求值脚本（接口 B）

目标信息和业务求值都写在同一个脚本里。`TARGET` 必须是**字面量字典**
（引擎在宿主侧用 AST 读取，不执行脚本）。

```python
TARGET = {
    "blend": r"C:\...\破碎修改器.blend",
    "object": "破碎立方体",
    "modifier": "破碎",
    "param": "碎片数量",
    "node_tree": "",   # 可选；留空表示用修改器的 node_group
}

def evaluate(ctx):
    for v in (20, 40):
        ctx.set_value(v)
        print(v, ctx.instance_count())
```

`ctx` 由底座注入：

| 字段 | 说明 |
|---|---|
| `ctx.bpy` | `bpy` 模块 |
| `ctx.target` | TARGET 的完整字典（含 CLI 覆盖后的生效值） |
| `ctx.obj` | 物体对象，来自 `TARGET["object"]` |
| `ctx.mod` | 修改器对象，来自 `TARGET["modifier"]` |
| `ctx.param` | 参数显示名，来自 `TARGET["param"]` |
| `ctx.set_value(v)` | 设参数并触发一次求值，返回耗时 ms |
| `ctx.instance_count()` | 当前 depsgraph 的实例数 |

- `TARGET["param"]` 用显示名，底座负责解析成真正的 socket identifier。
- `--blend/--obj/--mod/--param` 仍可作为可选覆盖项。
- `evaluate` 内可以多次求值；当前设计为**一个累计窗口**。

## 5. 运行流程

```text
python engine.py run --eval eval\frag2.py --node boolean \
  [--blend ... --obj ... --mod ... --param ...] \
  [--blender D:\blender-src\build_windows_x64_ClangCovTrace\bin\blender.exe] \
  [--out out]
```

1. 读取 eval 的 `TARGET` 和文件内容，算 `run_key`。
2. 计算 `hash8 = run_key[:8]`。
3. `out/<node>/<hash8>/run.json` 已存在且 key 相同：
   报错“你要的东西已经跑过了”，并打印目录。
4. 建 cache 工作目录 `cache/<node>/<hash8>.tmp/`。
5. 启动 Blender（不传 blend），传入 bootstrap、eval、node、work，
   以及闸门的 `module:Class` 列表。
6. bootstrap 读 TARGET、打开 blend、校验 object/modifier/param、
   解析 socket identifier、构造 ctx；然后 arm 闸门 → evaluate →
   反序 dump，落 raw 和 `status.json`。
7. 引擎做硬检查（`edge_count`、`functions.bin`、`window.profraw`），
   然后按顺序跑卡片，全部写入暂存输出目录。
8. 成功：暂存目录改名 `out/<node>/<hash8>/`，work 改名
   `cache/<node>/<hash8>/`；失败：work 改名
   `cache/<node>/<hash8>.failed-<timestamp>/`，保留现场。
9. 已有成功 cache 时，可以只重跑翻译，不启动 Blender：

```text
python engine.py translate cache/<node>/<hash8> [--out out]
```

## 6. 交互规则

### 6.1 节点名

- `--node` 同时用于：输出目录命名、between 卡片解析。
- 目录名安全化：非 `[A-Za-z0-9_.-]` 替换为 `_`。
- between 卡片解析顺序：
  1. 函数全名精确匹配；
  2. 唯一子串匹配；
  3. 多个候选里优先 `*::node_geo_exec`；
  4. 仍有多个 → 报错并列出候选。
- 解析失败时 raw 保留（见第 9 节），可只重跑翻译。

### 6.2 重复判定

```text
run_key = sha256(
    eval 内容
    + node
    + 构建指纹（exe/PDB 路径、大小、mtime）
    + 生效的 TARGET（含 CLI 覆盖）
)
hash8 = run_key 前 8 位
```

- 同一节点、同一脚本、同一构建 → 同一 `hash8` → 报错。
- 同一节点、不同脚本或不同构建 → 不同 `hash8` → 新目录。
- 失败重跑：允许 `--force` 覆盖同一 `hash8`（可选实现）。

### 6.3 产物命名

`out/<node>/<hash8>/` 下：

| 文件 | 内容 |
|---|---|
| `edge.json` | `meta / files / functions / edges`（沿用 format 2） |
| `return.json` | `meta / functions[].returns_to` |
| `between.json` | `meta / between[].{name,file,line}` |
| `coverage.json` | `meta / files[path].{count,ranges}`（执行行） |
| `run.json` | manifest：key、路径、时间、计数、卡片状态 |

不再产出：

- `no_edge`
- `start.json`
- `finally.json`

Start/Finally 在 `between` 卡片内部计算，不落中间文件。

## 7. 闸门与窗口细节

### 7.1 v1 闸门

| 闸门 | 导出符号 | raw 产物 |
|---|---|---|
| `calls` | `covtrace_calls_arm/reset/disarm/dump/dump_edges/dump_returns/edge_count/return_count` | `functions.bin`、`edges.bin`、`returns.bin`、`calls.json` |
| `coverage` | `covtrace_arm`、`covtrace_dump` | `window.profraw` |

`calls.json` 记录本次窗口的 `edge_count` / `return_count` 和 raw 路径；
bootstrap 另外写 `status.json` 供引擎判断成功/失败。

### 7.2 窗口顺序

```text
coverage arm
calls arm
calls reset
evaluate()
calls disarm
calls dump functions / edges / returns
coverage dump
```

- 行覆盖和函数边来自同一次执行、同一个窗口。
- 函数钩子使用 `-finstrument-functions-after-inlining`，caller 为函数入口。
- call/return 边在 frag2 上已验证 4312 对 4312 完全匹配。

### 7.3 构建产物

默认使用：

```text
D:\blender-src\build_windows_x64_ClangCovTrace\bin\blender.exe
D:\blender-src\build_windows_x64_ClangCovTrace\bin\blender.pdb
```

现有两个旧构建目录不覆盖、不参与。

## 8. 翻译卡片

### 8.1 edge

- 输入：`functions.bin`、`edges.bin`、exe/PDB。
- 输出：`edge.json`。
- 逻辑沿用 `btrace_symbolize.py`：RVA 反解为 `name/file/line/module`，
  调用边写成 `{caller, callee}` 下标。

### 8.2 return

- 输入：`edge.json`、`returns.bin`、exe/PDB。
- 输出：`return.json`。
- 逻辑沿用 `btrace_returns.py`：按 `(name, file, line)` 匹配重载，
  生成每个函数的 `returns_to` 列表。

### 8.3 between

- 输入：`edge.json`、`return.json`、`node`。
- 输出：`between.json`。
- 步骤：
  1. 解析 node → `*::node_geo_exec`；
  2. Start = 直接 return 给 node exec 的函数；
  3. Finally = 直接 return 给 Start 的函数；
  4. 在调用边上向下闭包 ∩ 在反向调用边上向上闭包；
  5. 输出平铺的 `{name,file,line}`。
- 逻辑沿用 `btrace_boundary_walk.py`，但不再读写 start/finally 中间文件。

### 8.4 coverage（可选，后续）

- 输入：`window.profraw`、exe/PDB。
- 输出：`coverage.json`。
- 逻辑沿用 `parse_coverage.py`：profraw → profdata → llvm-cov show →
  执行行区间。
- 与现有三张卡完全独立；加不加由需求决定。

## 9. 中间数据策略（已确定）

raw 不进 `out/`，放在独立的 cache：

```text
cache/<node>/<hash8>/
  functions.bin / edges.bin / returns.bin / window.profraw
  status.json / run.json / calls.json / coverage_raw.json
```

规则：

- 成功后保留 raw，便于只重跑翻译（尤其是 coverage 或卡片修复）。
- 失败时把 work 改名为 `<hash8>.failed-<timestamp>/`，保留现场。
- 每个节点默认保留最近 **5** 个 cache；`--keep-cache N` 可改，
  `0` 表示不清理。
- `--no-raw`：所有卡片成功后删除 raw（此时不能 translate）。
- `engine.py translate <cache_dir>`：用已有 raw 重跑四张卡，
  不启动 Blender；成功后原子替换 `out/<node>/<hash8>/`。

采集硬检查：`edge_count == 0`、`functions.bin` 为空、或
`window.profraw` 为空，都会判失败并保留 raw，避免“脚本没触发求值
但流程显示成功”。

引擎默认设置 `LLVM_PROFILE_FILE=NUL`，避免没有覆盖闸门时 Blender
在项目目录写出 `default.profraw`。

## 10. 错误处理

| 情况 | 行为 |
|---|---|
| 闸门缺导出符号 | 列出闸门名和缺失符号 |
| 重复 run key | 报错并打印已存在的 `out/<node>/<hash8>/` |
| node 解析歧义 | 列出所有候选函数全名 |
| 采集结果为空 | `edge_count=0` / `functions.bin` 空 / `window.profraw` 空 → 判失败，raw 改名 `.failed-*` 保留 |
| 卡片失败 | 不产生最终目录；raw 改名 `.failed-*` 保留 |
| Blender 退出码 `0xC0000409` | 视为正常；只要 raw 已完整写出就继续 |
| exe/PDB 不配对 | 翻译前检查，报错并停止 |

## 11. 扩展方式与“独立性”

### 11.1 注册在哪

注册只在 `engine.py`，由开发者显式维护，例如：

```python
from gates.calls import CallsGate
from cards.edge import EdgeCard
from cards.returns import ReturnsCard
from cards.between import BetweenCard

GATES = [CallsGate()]
CARDS = [EdgeCard(), ReturnsCard(), BetweenCard()]
```

- 运行时用户（AI）**不做注册**，只传 `--eval` 和 `--node`。
- 不使用自动扫描/插件发现：闸门 arm 顺序、卡片执行顺序都是固定的，
  避免隐式行为和顺序不确定。
- 以后加 coverage：新增 `gates/coverage.py`、`cards/coverage.py`，
  在 `engine.py` 的 `GATES` / `CARDS` 里各加一行即可。

### 11.2 “独立”指什么

- **代码解耦**：闸门之间不互相 import；卡片之间不互相 import；
  卡片不 import 闸门。所有模块只依赖 `infra/` 和引擎传入的 ctx。
- **互不影响**：改一张卡片的实现、加一个新闸门，不需要改其他卡片/
  闸门的代码。
- **只在 engine.py 会合**：模块的先后顺序、启用与否，由引擎的注册表决定。
- “独立”不是“运行时自己注册”，也不是“新增模块完全不用改任何现有代码”
  ——`engine.py` 里的那一行注册是唯一的显式接入点。

## 12. 实施顺序

按“一次只做一个模块”推进：

1. **基础设施 + 引擎骨架**
   - `paths`、`runkey`、`manifest`、重复检查、`out/<node>/<hash8>`。
   - 不跑 Blender，只验证目录和报错逻辑。
2. **calls 闸门 + bootstrap + 求值模板**
   - 端到端拿到 `functions.bin` / `edges.bin` / `returns.bin`。
3. **edge 翻译卡片**
   - 第一份最终 JSON。
4. **return 翻译卡片**
5. **between 翻译卡片**
   - 由 node 名补上最后一环。
6. **coverage 闸门 + coverage 卡片（已完成）**
   - 独立加入，不改前三张卡。
